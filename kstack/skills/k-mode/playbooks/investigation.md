# Investigation

**You own the answer. Read-only. The deliverable is a cited explanation or recommendation, not a change.**

1. Route through **k-explore**. For "why was it built this way", include its history pass.
2. Runtime symptoms (leak, spin, glitch) and captured artifacts (profile, trace, heap snapshot, crash log) are investigations too. Instrument or parse them. The deliverable is a diagnosis.
3. A decision between alternatives ends in a recommendation with a tradeoffs table. A question that needs external sources goes to **k-spectre**.
4. Throughput checkpoint is one line: `n/a, read-only investigation`.

If the answer leads to a code change, stop and re-route to Bug fix or Feature.

**Reply:** Overview, Key concepts, How it works, Where things live (paths), Gotchas. For "are we sure?", your real judgment with reasons. Push back when the premise is wrong.
